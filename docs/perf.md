# Performance

Measured on an Apple M1 Max (64 GB), macOS 27.0.1, ad-hoc-signed release build. A process-launch harness measured 348.9 ms from spawning the executable until a marker written immediately after the status item was constructed, with the event tap deferred until afterward. Five seconds after launch, `ps` reported 0.0% CPU and 53,344 KiB RSS; the event tap reported both permissions granted and active. The selected model was not loaded at startup. These are individual warm-cache observations while other applications were running, not a cold-launch distribution or sustained idle profile. The observed launch exceeds the requested 200 ms target. An earlier build that constructed the event tap before the status item measured 464.6 ms in the same harness.

Whisper tiny.en and Parakeet v3 transcribed the same synthesized WAV in CLI smoke tests. Largest-model loaded memory, cold-start distributions, and actual microphone-to-insertion latency have not yet been measured. Loading begins on first use or a model selection change, and the last selected engine is retained for subsequent recordings.

For end-to-end verification, a debug build used `say` to create a WAV, opened and stopped AVAudioEngine, and substituted that WAV at the capture boundary. A test-only distributed notification caused the app to post Option-Space at the HID event tap; the normal hotkey handler consumed it. Both Whisper tiny.en and Parakeet v3 inserted “This is a local speech recognition test.” into an empty TextEdit document, verified through its Accessibility value, without adding a non-breaking space. The direct debug toggle was also exercised with Parakeet. This does not measure real microphone sound quality or real capture latency.

A live test also played the same `say` sentence through the default speakers into the built-in microphone, without WAV substitution. Both engines inserted text into TextEdit via the HID shortcut: Whisper produced “This is a local speech recognition task.” and Parakeet produced “This is a local speech recognition chat.” Both misrecognized the final word in this acoustic setup.

Subsequent changes defer catalog/history loading and the settings hosting controller until after status-item construction, and move Accessibility IPC off the main actor. Cold-launch timing for this newer build has not yet been measured; inference dependencies are still linked into the app process.
